# DESIGN.md 设计与交付说明

投资组合分析与调仓模拟 · 全栈技术测评 · 文档编号 VC-FIN-001

## 1. 需求与交互

**核心用户流程**：组合查看（总资产/现金/持仓明细/行业分布）→ 集中度超限识别（单一标的、行业）→ 调仓模拟（按顺序添加多笔买卖、逐笔执行，或由**目标权重建议**一键生成买卖列表）→ 原组合 vs 模拟组合对比 → 方案命名保存 → 刷新/重启后重开查看；方案可删除、可载入模拟器派生新草稿。

**功能边界**：单用户、单组合、单币种（CNY）、固定行情快照价格；仅给定标的；无手续费（规则值为 0，引擎显式拒绝非零）、税费、分红、融资、卖空、真实下单。仅检查标的与行业集中度，不做收益预测与投资建议。**扩展功能**（超出任务书最小范围，均经测试验证）：目标权重调仓建议（等权分散 / 自定义权重 + 偏差报告）、方案删除（二次确认）、方案载入模拟器派生草稿（原方案为只读快照，不被覆盖）。

**验收条件**：FR-01~FR-05 分别对应组合概览、集中度检查、调仓模拟、方案持久化、后端计算与校验；基准验收用例 AC-01~AC-05 的数值见 VERIFY.md，均通过。

**需求拆解：FR → 实现 → 验证映射**

| 功能要求 | 实现位置 | 验收 |
|---|---|---|
| FR-01 组合概览 | `GET /api/portfolio` + 前端 Overview（统计卡/持仓明细/行业分布） | AC-01、截图 01 |
| FR-02 集中度检查 | 引擎 `analyze()`：Fraction 精确阈值比较（严格大于） | AC-01/02、test_money 边界 |
| FR-03 调仓模拟 | `POST /api/simulate` + SimulationPanel/CompareTable（逐笔执行、遇错即停） | AC-02/03/04 |
| FR-04 方案持久化 | SQLite plans/snapshots 两张表 + `POST/GET /api/plans` | AC-05（含服务重启复验） |
| FR-05 后端计算与校验 | `engine.py` 纯函数为业务规则唯一实现 + 统一错误语义 | AC-04、test_api_acceptance |
| 扩展 | `POST /api/rebalance`、`DELETE /api/plans/{id}`、前端 RebalancePanel | EX-01~07（VERIFY.md §2b） |

**状态与失败交互**（页面级约定）：
| 状态 | 交互 |
|---|---|
| 组合加载中 | 「加载中…」占位 |
| 组合加载失败（后端未启动等） | 错误横幅 + 重试按钮 + 启动提示 |
| 无操作的空模拟 | 占位提示「尚未添加操作」；对比表提示「添加操作后将在此展示对比结果」 |
| 某笔操作校验失败 | 该行红色高亮 + 行内中文错误（含原因与数值）；其后操作置灰标「未执行」；已生效操作不受影响；保存按钮禁用 |
| 方案重名 / 非法名称 / 空方案 | 保存框下方内联错误（后端 409/422，中文 message） |
| 方案不存在 | 内联错误「方案不存在」 |

## 2. 数据与状态

```
种子 JSON（data/投资组合示例数据.json）
  └─ 解析(parse_portfolio) → PortfolioState(现金分 + 持仓) + InstrumentDef[] + Rules
        ├─ 原组合（只读，frozen dataclass，从不写入数据库）
        └─ 模拟：copy-on-write 逐笔生成新状态（天然隔离，见 §5 决策 4）
SQLite（backend/portfolio.db）
  ├─ snapshots(snapshot_id PK, ..., payload)  启动时 INSERT OR IGNORE 种子 JSON 整体入库
  └─ plans(id PK, name UNIQUE, snapshot_id FK, ops_json, created_at)
```

- **原始数据隔离**：原组合状态为 frozen dataclass，任何模拟通过 `replace()` 复制出新状态；服务每次请求都从同一解析结果出发，原始组合在任何操作下不变（AC-05 已验证）。
- **保存内容**：方案仅保存 `ops_json`（操作列表）与 `snapshot_id`，不保存计算结果。
- **重新计算策略**：重开方案时由后端按操作列表对库内快照重新计算。操作列表是唯一事实来源；固定价格 + 零费用使重算确定，缓存结果反而存在漂移风险（§5 决策 1、2）。
- **快照关联**：方案 → snapshot_id → 库内 payload。即使种子文件日后被替换，历史方案仍按保存时的快照重算。

## 3. 系统结构与接口

```
浏览器（React 18 + Vite + TS，构建产物 dist/）
   │  /api/* 与静态页面
   ▼
FastAPI（main.py：路由 + StaticFiles 托管 dist + SQLite 初始化）
   ├─ routers/portfolio.py   GET /api/portfolio
   ├─ routers/plans.py       POST /api/simulate · POST/GET/DELETE /api/plans[/{id}]
   ├─ routers/rebalance.py   POST /api/rebalance（目标权重调仓建议）
   ├─ engine.py（纯函数计算引擎，无 I/O，业务规则唯一实现，含 suggest_rebalance）
   ├─ money.py（整数分 + Fraction 精度）
   ├─ db.py（sqlite3，每请求短连接）
   └─ SQLite 文件
```

| 接口 | 请求 | 成功响应 | 失败 |
|---|---|---|---|
| `GET /api/portfolio` | — | 组合概要 + 持仓明细 + 行业占比 + 集中度触发列表 + 规则，数值均为后端预格式化字符串 | 500 |
| `POST /api/simulate` | `{operations:[{action:"BUY"/"SELL",symbol,quantity}]}` | 200：`applied[]`（逐笔含金额与执行后现金）、`simulated`、`analysis`、`original_analysis`、`error` | 结构错误 422 |
| `POST /api/plans` | `{name, operations}` | 201：方案摘要 | 无效操作/非法名/空方案 422；重名 409 |
| `GET /api/plans` | — | 200：方案列表（新→旧） | — |
| `GET /api/plans/{id}` | — | 200：重算后的完整方案（同 simulate 结构） | 404 |
| `DELETE /api/plans/{id}` | — | 204 | 404 |
| `POST /api/rebalance` | `{mode:"equal"}` 或 `{mode:"targets", targets:{"A01":"0.25"}}` | 200：建议操作（引擎校验后）+ 模拟结果 + 目标/实际偏差报告 | 空目标/未知标的/权重非法/权重和>1 → 422 |

错误体统一 `{"detail": {"code", "message"}}`，中文 message；前端兼容 FastAPI 结构校验错误的数组形态。

**口径统一（FR-05）**：所有金额、占比、阈值比较、约束校验都在后端引擎内完成；前端只渲染字符串与交互，不做任何金额/占比计算，杜绝前后端口径不一致。

## 4. 计算与异常

**精度方案**：金额一律以「分」为单位整数（int）运算；占比为 `Fraction` 精确有理数；阈值比较发生在任何展示舍入之前（`strictly_greater_than`，等于阈值不触发——AC-02 的 30%/50% 边界已测）；展示层统一 `ROUND_HALF_UP` 两位小数（1/3 → 33.33% 边界已测）。float 不参与任何计算；`Fraction`/`Decimal` 只从字符串构造，避免二进制浮点误差。

**计算验证方法**：① 单元测试直接断言「分」级精确值与展示字符串；② 独立复算函数 `total_cents()` 与引擎交叉核对总资产不变式；③ API 验收测试断言 JSON 字符串；④ 手工 curl 与浏览器 DOM 核验（VERIFY.md）。

**异常设计**：价格缺失/字段非法 → 启动解析即失败（快速失败，数据文件随交付物提供）；行业未知 → 归入「未知行业」中性色分组展示（任务书允许仅说明设计）；费用非零 → 引擎显式拒绝（本次范围仅支持 0）；数量上限 10⁹ 防极端输入。

## 5. 设计决策（含备选方案）

1. **操作列表为唯一事实来源，结果读取时重算，不持久化计算结果**（备选：保存计算结果 JSON）。备选会引入 ops 与结果漂移风险，而重算为 O(n) 整数运算，缓存毫无收益。选重算。
2. **快照 payload 整体入库，方案只存 snapshot_id**（备选：方案引用种子文件路径）。备选下种子文件被替换会改变历史方案结果；入库使历史方案自洽，且顺手获得重开时的数据完整性。选入库。
3. **操作级校验失败返回 200 + 内嵌 `error`**（备选：422 拒绝整个请求）。任务书要求「校验失败不得改变有效模拟结果」——有效前缀状态本身就是前端需要的输出；422 会丢弃前缀状态，迫使前端自维护并行状态。保存接口仍严格 422（保存前完整重校验）。选内嵌 error。
4. **金额用整数分 + Fraction**（备选：`Decimal` 全程；`float`）。Decimal 需要论证精度上下文与舍入模式；float 直接出局（0.1 无法精确表示）。整数分 + 有理数无需任何上下文，设计文档最好解释。选整数分 + Fraction。
5. **前端不引入路由库，单页分区 + 页签**（备选：react-router 多路由）。页面组织简单、无深链需求；免去 SPA 回退配置。为截图与验收可复现，提供 `?tab=`、`?ops=`、`?plan=` URL 参数作为验证辅助入口。选无路由。
6. **SQLite 文件而非 JSON 文件存储方案**（备选：JSON）。SQLite 免费获得 UNIQUE 重名约束、事务与断电安全性，且零额外依赖（stdlib sqlite3）。选 SQLite。
7. **调仓建议复用顺序模拟引擎校验**（备选：建议独立实现一套校验逻辑）。建议生成（先卖后买、整数股数半入取整、现金不足逐股减量）后，用与人工操作完全相同的 `simulate_sequential` 校验，保证"建议"与"手工"永远同一口径、同一错误语义；备选方案必然产生口径漂移与双重维护。选复用引擎。

## 7. AI 协作记录

**工具与环节**：全程使用 Claude Code（CLI 会话）作为 AI 编程助手：需求拆解与验收数值验算、架构设计、代码生成（后端引擎/接口/前端组件/测试）、文档草拟。人工负责：需求与设计确认、关键数值复核、验收执行与截图、本记录撰写。

**片段 1 —— 验收数值先验算**。向 AI 提供任务书与示例 JSON，要求先独立复算 AC 数值再开工。AI 输出：总资产 100,000（现金 20,000 + 持仓 80,000）；卖 A01×100 后 30%/50% 恰好不触发；再买 A02×100 后科技 55% 触发。**检查方法**：人工笔算复核一致后采纳，并作为全部测试的期望值来源。

**片段 2 —— 测试暴露 AI 生成的测试用例错误**。AI 编写「中途失败」用例时假设「卖 A01×100 后买 A01×201 会现金不足」，pytest 执行失败显示该序列实际**应成功**（卖出后现金 30,000 ≥ 20,100）。**核验过程**：人工复算确认引擎行为正确、是测试期望值错误——这正是任务书 AC-04 强调的「后续操作使用前序结果」；将第二笔改为 ×301（30,100 > 30,000）后测试通过。该案例说明：AI 生成的代码与测试都不能直接采信，必须运行验证并独立复算。

**片段 3 —— 配色规范校验**。AI 按数据可视化规范（dataviz 技能）为行业分布图生成调色板，运行 `validate_palette.js` 校验：浅色模式 aqua/yellow 对比度 <3:1（WARN）。**处理**：按规范要求采取缓解——每个条形直接标注名称与百分比、附表格视图，颜色不单独表意；深色模式单独选色并校验通过。校验结果作为采用依据。

**其他检查方法**：pytest 67 用例全绿；curl 逐接口核对 AC 数值；Chrome headless `--dump-dom` 验证真实浏览器中渲染结果；5 张验收截图（01 逐项目视核对，扩展功能页 DOM 核验）。

**实际投入时间**：约 1.3 小时（11:31 开工 → 12:45 前后完成全部交付物；git 提交时间戳可追溯：PLAN 11:32、引擎 11:36、API 11:39、前端 11:59、验证 12:00~12:05、扩展功能 12:10~12:35、文档收尾 12:37~12:45）。AI 辅助显著压缩了编码与测试时间，主要精力用于设计确认与验证。低于任务书建议的 3–4 小时，如实说明。
