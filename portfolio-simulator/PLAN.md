# 开工方案 PLAN.md

## 需求理解

基于固定行情快照（2026-11-02 15:00，北京时间）的单用户、单组合、单币种（CNY）组合分析原型。核心流程：**组合查看 → 集中度超限识别 → 顺序调仓模拟（原组合 vs 模拟组合对比）→ 方案命名保存与重开**。

关键规则：单一标的占比 >30%、行业占比 >50% 触发提醒（**等于不触发**，`strictly_greater_than`，比较用展示舍入前的数值）；现金计入总资产分母、不归入任何行业；数量必须为正整数；现金不可为负；卖出不得超过当前模拟持仓；模拟从原始组合出发逐笔执行、后续操作使用前序结果、校验失败不得改变有效模拟结果；费用为 0，模拟前后总资产不变；原始组合与方案相互隔离，方案需支持重启服务后重开。

验收口径：AC-01~AC-05（初始总资产 100,000、A01 40% 与科技 60% 均触发；卖 A01×100 后 30%/50% 恰好解除；再买 A02×100 后科技 55% 重新触发；买 A01×201 / 卖 A01×401 / 零负小数数量均被拒绝且不改变有效结果；保存 AC-03 方案后重启重开结果不变、原始组合不受影响）。

## 待确认问题与假设

| # | 问题 | 假设与处理 |
|---|---|---|
| 1 | 技术栈、存储、页面组织未指定 | 自选：FastAPI + SQLite + React/Vite，理由见"技术选择" |
| 2 | 方案重名 | 不允许，后端 409 提示换名（名称 trim、1–50 字） |
| 3 | 方案编辑/删除 | 不实现（任务书明确"不要求"） |

| 6 | 并发/多用户 | 单机单用户假设，SQLite 本地文件 |

## 最小实现范围

- 后端：组合概览+集中度分析接口；模拟预览接口（逐笔校验、遇错即停）；方案保存/列表/重开接口；SQLite 持久化。
- 前端：单页四区块（组合概览、集中度检查、调仓模拟+前后对比表、已存方案与重开）；操作级错误内联反馈。
- 文档：README（运行说明）、DESIGN（设计、决策、AI 协作记录、复盘）、VERIFY（AC-01~05 验证记录+截图）。

## 技术选择

- 后端：Python 3.13 + FastAPI + sqlite3（标准库）；金额内部用**整数"分"**，占比用 **Fraction 精确比较**，展示层 ROUND_HALF_UP 两位小数。
- 前端：React 18 + Vite + TypeScript，构建产物由 FastAPI 托管（评审者无需 npm dev 即可访问）。
- 测试：pytest（引擎单元测试 + TestClient API 验收测试）。
- 取舍：SQLite 文件而非 JSON 文件——获得唯一性约束与重启恢复；不引入 ORM、前端状态库与路由库——规模不需要，依赖越少评审越易复现。

## AI 协作步骤

1. 向 AI 提供任务书、示例数据与完成标准（AC 用例数值），请其先独立验算验收数值，人工复核后再开工。
2. 关键设计（精度方案、接口与错误语义、存储策略）先由 AI 提出方案，人工确认后生成代码。
3. 对 AI 输出：逐条跑验收用例、独立复算关键数值、补充边界用例（阈值相等、舍入边界、中途失败）核验；记录至少一次实际核验过程于 DESIGN.md。

## 验证计划

- pytest 全绿：AC-01~05 映射到引擎与 API 测试用例；AC-05 用同一 DB 文件新建应用实例模拟"服务重启"。
- 手工端到端：启动服务，走通 查看 → 超限识别 → 模拟 → 对比 → 保存 → 重启 → 重开，截图入 VERIFY.md。
- 交叉验算：总资产不变式、30%/50% 阈值边界、20,100 > 20,000 现金不足等用独立计算复核。
